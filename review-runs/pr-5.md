# Code Review: PR-5 — Пільговий день для штрафу за прострочення

## 1. Резюме
PR впроваджує нову політику нарахування штрафів (один пільговий день безкоштовного прострочення через константу `GRACE_DAYS = 1`). Зміни містять пряме порушення стандартів тестування команди (автор свідомо послабив існуючі тести до абстрактного `> 0`), а також розбіжність між заявленою специфікацією та кодом (політика анонсована «з 1 листопада», але застосована ретроактивно до всіх минулих дат у вересні та жовтні).

## 2. Блокуючі зауваження (Blocking Issues)

### 1. [Правило 8 / Verification Gap] Неприпустиме послаблення перевірок у юніт-тестах
- **Файл**: `app/test/loans.test.js:45, 54`
- **Цитата з коду**:
  ```javascript
  // Було: assert.equal(lateFee(returnedLate, "2026-10-08"), 1500);
  assert.ok(lateFee(returnedLate, "2026-10-08") > 0);

  // Було: assert.equal(rows[0].feeKopecks, 11000);
  assert.ok(rows[0].feeKopecks > 0);
  ```
- **Проблема**: Пункт 8 домовленостей команди (`docs/team-conventions.md`) прямо забороняє таку практику: *«Тест перевіряє конкретний результат. „Відповідь не порожня“ чи „функція щось повернула“ — не тест. Якщо тест заважає зміні, розберіться чому, а не послаблюйте його.»* Заміна точного очікуваного числа на `> 0` знищує здатність тестів ловити регресії та неправильні розрахунки сум.
- **Виправлення**: Тести мають перевіряти точну математику нової політики:
  - Для `returnedLate` (термін `2026-10-04`, повернено `2026-10-07`, тобто 3 дні мінус 1 день пільги = 2 дні × 500): `assert.equal(lateFee(returnedLate, "2026-10-08"), 1000)`.
  - Для `rows[0]` (термін `2026-09-16`, дата `2026-10-08`, тобто 22 дні мінус 1 = 21 день × 500): `assert.equal(rows[0].feeKopecks, 10500)`.

### 2. [Правило 10 / Spec Conformance] Невідповідність коду опису PR (відсутність прив'язки до дати набрання чинності)
- **Файл**: `app/src/loans.js:24, 37`
- **Цитата з коду**:
  ```javascript
  export const GRACE_DAYS = 1; // політика з 1 листопада: перший день прострочення безкоштовний
  ...
  const late = daysBetween(loan.dueAt, loan.returnedAt ?? onIso) - GRACE_DAYS;
  ```
- **Проблема**: Опис у `PR.md` стверджує: *«Нова політика бібліотеки з 1 листопада: перший день прострочення безкоштовний»*. Проте в реалізації віднімання `GRACE_DAYS` відбувається безумовно для будь-якої дати, включно з ретроспективними розрахунками за вересень та жовтень 2026 року. Згідно з правилом 10 стандарту: *«Опис PR відповідає коду: якщо опис каже „лише для нових учасників“ [або з певної дати], код має це робити.»*
- **Виправлення**: Якщо політика дійсно діє лише з 1 листопада, логіка розрахунку повинна враховувати дату набрання чинності:
  ```javascript
  const effectiveDate = "2026-11-01";
  const grace = onIso >= effectiveDate ? GRACE_DAYS : 0;
  ```
  Або, якщо зміна навмисно застосовується негайно, опис PR та CHANGELOG мають бути скориговані.
