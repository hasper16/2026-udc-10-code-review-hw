# Code Review: PR-2 — Email учасника у звіті про прострочення

## 1. Резюме
PR розширює звіт про прострочені позики `overdueReport`, додаючи контактний email учасника для зв'язку та форматоване текстове поле штрафу `feeText`. Зміни містять прямі порушення стандартів команди: відсутній обов'язковий аудит доступу до персональних даних (PII), порушено правило передачі фінансів в API (додано форматований рядок замість виключно копійок), не оновлено CHANGELOG, а також погіршено продуктивність через лінійний пошук і подвійні виклики.
**Вердикт: ЗАБЛОКОВАНО (Changes Requested)**.

## 2. Блокуючі зауваження (Blocking Issues)

### 1. [Правило 2 / Стандарт] Відсутній запис у журнал аудиту персональних даних (`logAccess`)
- **Файл**: `app/src/loans.js:16`
- **Цитата з коду**:
  ```javascript
  email: db.findMember(l.memberId)?.email ?? null,
  ```
- **Проблема**: Згідно з пунктом 2 домовленостей команди (`docs/team-conventions.md`), email та телефон є персональними даними: *«Будь-яка функція, що їх повертає, записує доступ у журнал: `logAccess(db, user, memberId, purpose)` з `src/audit.js`, один запис на кожного учасника, чиї дані віддано. Так ми відповідаємо на питання „хто і навіщо дивився мої дані“.»* Додавання поля `email` у звіт повертає PII без жодного фіксування в `accessLog`.
- **Виправлення**: Для кожного унікального `memberId`, чиї персональні дані потрапили у звіт, викликати `logAccess(db, user, l.memberId, "overdue-report")` (або зафіксувати доступ для кожного рядка).

### 2. [Правило 4 / Стандарт] Форматування грошей у коді `src/` замість клієнта (`feeText`)
- **Файл**: `app/src/loans.js:20`
- **Цитата з коду**:
  ```javascript
  feeText: (lateFee(l, todayIso) / 100).toFixed(2).replace(".", ",") + " грн",
  ```
- **Проблема**: Пункт 4 домовленостей команди чітко забороняє текстове форматування валют у бекенді: *«Гроші в API — лише цілими копійками (`…Kopecks`). Форматування для людей („15,00 грн“) робить клієнт, а не `src/`.»* Додавання `feeText` у JSON-відповідь порушує дизайн контракту та архітектурне розмежування відповідальності.
- **Виправлення**: Видалити поле `feeText` з об'єкта звіту; на клієнті використовувати наявне поле `feeKopecks`.

### 3. [Правило 6 / Стандарт] Відсутнє оновлення `app/CHANGELOG.md`
- **Файл**: `app/CHANGELOG.md`
- **Проблема**: Змінено сигнатуру/структуру даних, що повертаються публічною функцією `overdueReport` (додано поле `email`). Згідно з правилом 6, будь-яка зміна повернутого значення вимагає обов'язкового запису в `app/CHANGELOG.md` у тому ж PR.
- **Виправлення**: Додати запис про додавання email до `overdueReport` у секцію `## 2026-10`.

## 3. Зауваження та дрібниці (Non-blocking / Nits)

### 1. [Fowler Smell / Performance] Деградація продуктивності через лінійний пошук (N+1)
- **Файл**: `app/src/loans.js:15-16`
- **Цитата з коду**:
  ```javascript
  member: db.findMember(l.memberId)?.name ?? "—",
  email: db.findMember(l.memberId)?.email ?? null,
  ```
- **Проблема**: Було видалено кешовану таблицю `const names = new Map(...)`, яка виконувала попередню індексацію учасників за O(M). Натомість для кожного рядка позики тепер двічі викликається `db.findMember(l.memberId)`, який робить лінійний перебір масиву `db.members`.
- **Рекомендація**: Зберегти або розширити попереднє мапування:
  ```javascript
  const members = new Map(db.members.map((m) => [m.id, m]));
  ```

### 2. [Fowler Smell / Duplicated Code] Подвійний виклик `lateFee`
- **Файл**: `app/src/loans.js:19-20`
- Розрахунок `lateFee(l, todayIso)` викликається двічі для кожної позики: для `feeKopecks` та для `feeText`. Оскільки `feeText` має бути видалено згідно з Правилом 4, проблема вирішиться автоматично.

## 4. Аналіз тестів та верифікації
- Тест перевірив додавання `rows[0].email`, але не верифікував журнал аудиту `db.accessLog`.
- Тест не зафіксував заборонене поле `feeText` як порушення, оскільки в тестах немає валідації схеми відповіді.
