# Code Review: PR-1 — Сторінкування для списку позик

## 1. Резюме
PR додає функцію `listLoansPage` для розбиття списку позик на сторінки у відповідь на зростання кількості записів. Реалізація містить критичну логічну помилку в обчисленні зміщення пагінації (off-by-one), відсутність обмеження максимального розміру сторінки, відсутність оновлення CHANGELOG та поверхневий тест, який не помітив повернення порожнього списку елементів.
**Вердикт: ЗАБЛОКОВАНО (Changes Requested)**.

## 2. Блокуючі зауваження (Blocking Issues)

### 1. [Правило 7 / Edge Cases] Критична помилка обчислення зміщення сторінки (Off-by-one)
- **Файл**: `app/src/loans.js:28`
- **Цитата з коду**:
  ```javascript
  const start = page * pageSize;
  ```
- **Проблема**: При номері сторінки за замовчуванням `page = 1` та `pageSize = 20`, розрахунковий індекс початку вибірки становить `start = 1 * 20 = 20`. У результаті перша сторінка повністю пропускає перші 20 записів (індекси 0–19), а для списків із меншою за 20 кількістю елементів (як у тестовій базі з 7 позиками) повертає порожній масив `items: []`.
- **Виправлення**: Обчислювати індекс як `(page - 1) * pageSize`:
  ```javascript
  const pageNum = Math.max(1, Number(page) || 1);
  const start = (pageNum - 1) * pageSize;
  ```

### 2. [Правило 7 / Стандарт] Відсутність верхньої межі для `pageSize`
- **Файл**: `app/src/loans.js:27`
- **Цитата з коду**:
  ```javascript
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
  ```
- **Проблема**: Згідно з пунктом 7 домовленостей команди (`docs/team-conventions.md`), списки мають бути зі «сторінкові, з обмеженим розміром сторінки». Наразі клієнт може передати `pageSize: 100000` або від'ємне число, що нівелює захист від перевантаження.
- **Виправлення**: Обмежити розмір сторінки фіксованим максимумом (наприклад, `Math.min(100, Math.max(1, Number(pageSize) || 20))`).

### 3. [Правило 6 / Стандарт] Відсутній запис у `app/CHANGELOG.md`
- **Файл**: `app/CHANGELOG.md`
- **Проблема**: Додано нову публічну функцію модуля `listLoansPage`, яка змінює публічний інтерфейс сервісу. За правилом 6 домовленостей команди: *«Будь-яка зміна того, що публічна функція в `src/` приймає або повертає, — запис у `app/CHANGELOG.md` у тому самому PR. Нова функція — теж зміна.»* У PR файл CHANGELOG.md не змінювався.
- **Виправлення**: Додати розділ `## 2026-10` з описом функції `listLoansPage(db, user, options)` у `app/CHANGELOG.md`.

### 4. [Правило 8 / Verification Gap] Слабкий тест: відсутня перевірка повернутих елементів (`items`)
- **Файл**: `app/test/loans.test.js:36-41`
- **Цитата з коду**:
  ```javascript
  test("paged list reports the total and the page it returned", () => {
    const res = listLoansPage(createDb(), iryna, { page: 1, pageSize: 20 });
    assert.equal(res.total, 7);
    assert.equal(res.page, 1);
    assert.equal(res.pageSize, 20);
  });
  ```
- **Проблема**: Тест перевіряє виключно метадані (`total`, `page`, `pageSize`), повністю ігноруючи масив `res.items`. Якби тест перевірив `assert.equal(res.items.length, 7)` або вміст першого елемента, він би негайно впав через баг `start = page * pageSize`, де `res.items` дорівнює `[]`. Це пряме порушення правила 8: *«Тест перевіряє конкретний результат. „Відповідь не порожня“ чи „функція щось повернула“ — не тест.»*
- **Виправлення**: Додати перевірку кількості та ідентифікаторів повернутих елементів у `res.items`.

## 3. Зауваження та дрібниці (Non-blocking / Nits)
- **Fowler Smell (In-memory overhead):** `listLoansPage` викликає `listLoans(db, user)`, який робить копіювання всіх об'єктів масиву в пам'яті (`rows.map((l) => ({ ...l }))`) до виконання `slice`. Для in-memory сховища це допустимо, але при переході на повноцінну БД пагінація має виконуватися на рівні запиту до сховища.
- **JSDoc vs Поведінка:** JSDoc коментар вказує `Paged variant for the staff UI`, проте авторизація всередині delegating-функції дозволяє виклик і звичайним учасникам (повертаючи лише їхні позики). Варто або узгодити опис у документації, або явно обмежити доступ роллю `STAFF`, якщо метод призначений суто для персоналу.
