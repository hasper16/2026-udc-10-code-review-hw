# Code Review: PR-2 — Email учасника у звіті про прострочення

## 1. Резюме
PR додає до кожного рядка `overdueReport` поле `email` учасника (заявлено в описі), а також — без жодної згадки в описі — поле `feeText` із відформатованою для людини сумою («110,00 грн»). Попутно прибрано наявну оптимізацію (`Map` імен) на користь подвійного `db.findMember` для кожного рядка. Email віддається без запису в журнал доступу до PII, публічний контракт змінено без запису в `app/CHANGELOG.md`, а рядкова сума прямо заборонена стандартом.

Вердикт: **ЗАБЛОКОВАНО (BLOCK)**.

## 2. Блокуючі зауваження (Blocking Issues)

- **[Правило 2] Email учасника повертається без `logAccess`**: `overdueReport` тепер віддає email для кожного учасника з простроченою позикою, але не викликає `logAccess(db, user, memberId, purpose)` з `src/audit.js`. Те, що звіт лише для персоналу, не звільняє від аудиту — правило вимагає запису для **кожного** учасника, чиї дані надано (порівн. `memberCard` у `src/members.js`, який логує `"member-card"`). Виправлення: для кожного рядка з email викликати `logAccess(db, user, l.memberId, "overdue-report")` (або один раз на унікального `memberId`, якщо політика це допускає — але так, щоб кожен учасник мав запис).
  - **Файл та контекст**: `app/src/loans.js`, `overdueReport`
  - **Цитата з коду**: `email: db.findMember(l.memberId)?.email ?? null,`

- **[Правило 4] Форматована рядкова сума у публічному API**: додано `feeText`, що будує людиночитане представлення суми з десятковою комою та позначенням валюти. Стандарт дозволяє в `src/` лише цілі копійки (`feeKopecks`, яке вже є); форматування — справа клієнта. Виправлення: видалити `feeText`.
  - **Файл та контекст**: `app/src/loans.js`, `overdueReport`
  - **Цитата з коду**: `feeText: (lateFee(l, todayIso) / 100).toFixed(2).replace(".", ",") + " грн",`

- **[Правило 10] Scope creep: незаявлене поле `feeText`**: опис PR говорить лише про ім'я та email; поле `feeText` в описі не згадується. Незаявлена зміна контракту — блокер окремо від Правила 4. Виправлення: прибрати поле (або, якщо воно справді потрібне, — винести в окремий PR із описом; але через Правило 4 у `src/` воно все одно неприпустиме).
  - **Файл та контекст**: `app/src/loans.js`
  - **Цитата з коду**: `feeText: (lateFee(l, todayIso) / 100)...`

- **[Правило 6] Немає запису в `app/CHANGELOG.md`**: змінено те, що повертає публічна функція `overdueReport` (нові поля `email`, `feeText`), але `app/CHANGELOG.md` у дифі не змінено; чинний запис перелічує лише `loanId`, `member`, `book`, `daysLate`, `feeKopecks`. Виправлення: додати запис про нове поле `email` (і про логування доступу в журнал).
  - **Файл та контекст**: `app/CHANGELOG.md` (відсутня зміна), `app/src/loans.js`
  - **Цитата з коду**: `+      email: db.findMember(l.memberId)?.email ?? null,`

## 3. Зауваження та дрібниці (Non-blocking / Nits)
- **[Правило 12] Прибрано наявну оптимізацію, N+1 і повторні пошуки**: раніше імена бралися з попередньо побудованої `Map` (O(1) на рядок); тепер для кожного рядка двічі викликається `db.findMember(l.memberId)` (лінійний пошук по `members`) — повторне звернення до сховища за тією самою сутністю в одній ітерації. Краще: один раз `const m = db.findMember(l.memberId)` на рядок, або повернути `Map` id → member.
- **[Правило 12] Подвійний виклик `lateFee`** для того самого рядка (`feeKopecks` і `feeText`) — зникне разом із `feeText`.
- JSDoc `overdueReport` («with the member's name») не оновлено — варто згадати email і те, що доступ журналюється.
- `email: ... ?? null` при `member: ... ?? "—"` — непослідовні заглушки для відсутнього учасника; дрібниця, але варто узгодити й задокументувати.

## 4. Аналіз тестів та верифікації
- Наявні твердження не послаблено; додано точну перевірку `rows[0].email === "marko@example.invalid"` — це конкретне значення, добре.
- **Розрив верифікації (Правило 2):** немає тесту, що після виклику `overdueReport` у `db.accessLog` з'являються записи для кожного учасника, чий email повернуто (очікувано memberId 5, 2, 1 для дати `2026-10-08`, з `by: 3`). Саме такий тест виявив би відсутність `logAccess`.
- Email перевірено лише для першого рядка; варто перевірити й решту (`taras@…`, `olya@…`) та випадок відсутнього учасника (`null`).
- `feeText` не покрито тестами взагалі (і не має існувати — див. Правило 4).
- Тест на `AccessDenied` для учасника з роллю `member` уже є («the overdue report is staff-only») — Правило 9 тут не порушене, нова функція не додається.
