# Code Review: PR-1 — Сторінкування для списку позик

## 1. Резюме
У PR додано нову публічну функцію `listLoansPage(db, user, { page, pageSize })` у `app/src/loans.js` для посторінкового отримання списку позик, а також один базовий юніт-тест у `app/test/loans.test.js`.

Попри невеликий обсяг змін, PR містить критичну помилку **off-by-one** у розрахунку зміщення сторінки (через що перша сторінка пропускає перші `pageSize` записів і в тесті повертає порожній масив `items: []`), не має валідації меж параметрів пагінації, не оновлює `app/CHANGELOG.md`, а доданий тест перевіряє лише метадані відповіді, ігноруючи сам масив `items`.

Загальний вердикт: **ЗАБЛОКОВАНО (BLOCK)**.

## 2. Блокуючі зауваження (Blocking Issues)

- **[Правило 7] Помилка off-by-one при обчисленні початкового індексу сторінки (`start`) та відсутність валідації меж пагінації**:
  При `page = 1` і `pageSize = 20` вираз `const start = page * pageSize` обчислює `start = 20` замість `0`. У результаті виклик для першої сторінки пропускає перші 20 записів (а для тестової бази з 7 позик `res.items` стає порожнім масивом `[]`). Крім того, відсутня перевірка коректності `page` (`page >= 1`) та обмеження `pageSize` (наприклад, `1 <= pageSize <= MAX_PAGE_SIZE`), що дозволяє передати від'ємні, нульові або надмірно великі значення.
  **Як виправити:** Використовувати формулу `const start = (page - 1) * pageSize;` та додати валідацію параметрів `page` і `pageSize` (перевірка на цілі числа, `page >= 1`, `1 <= pageSize <= MAX_PAGE_SIZE`).
  - **Файл та контекст**: `app/src/loans.js` (рядки 10–14 у дифі)
  - **Цитата з коду**:
    ```js
    export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
      const all = listLoans(db, user);
      const start = page * pageSize;
      return { items: all.slice(start, start + pageSize), page, pageSize, total: all.length };
    }
    ```

- **[Правило 8] Верифікаційний розрив у тесті — відсутність перевірки фактичних даних (`res.items`)**:
  Новий тест у `app/test/loans.test.js` перевіряє лише метадані (`res.total`, `res.page`, `res.pageSize`), які просто повертаються з аргументів функції та довжини масиву, але взагалі не перевіряє вміст чи довжину `res.items`. Саме через це тест проходить зеленим, хоча функція повертає `items: []` замість 7 очікуваних позик.
  **Як виправити:** Додати строгі перевірки вмісту `res.items` (наприклад, `assert.equal(res.items.length, 7)` та `assert.deepEqual(res.items.map((l) => l.id), [1, 2, 3, 4, 5, 6, 7])`), а також протестувати реальне розбиття на кілька сторінок (наприклад, `page: 1, pageSize: 3` та `page: 2, pageSize: 3`).
  - **Файл та контекст**: `app/test/loans.test.js` (рядки 36–41 у дифі)
  - **Цитата з коду**:
    ```js
    test("paged list reports the total and the page it returned", () => {
      const res = listLoansPage(createDb(), iryna, { page: 1, pageSize: 20 });
      assert.equal(res.total, 7);
      assert.equal(res.page, 1);
      assert.equal(res.pageSize, 20);
    });
    ```

- **[Правило 6] Відсутній запис у `app/CHANGELOG.md` для нової публічної функції API**:
  У модуль `app/src/loans.js` додано нову експортовану функцію `listLoansPage`, проте файл `app/CHANGELOG.md` не був оновлений у цьому PR.

  - **Файл та контекст**: `app/src/loans.js` та `app/CHANGELOG.md`
  - **Цитата з коду**:

## 3. Зауваження та дрібниці (Non-blocking / Nits)
- **[Правило 10] Неточність у JSDoc щодо ролей користувачів**: Коментар `/** Paged variant for the staff UI: { items, page, pageSize, total }. */` створює враження, що функція призначена лише для персоналу, хоча фактично вона делегує вибірку `listLoans(db, user)`, яка безпечно працює і для `staff` (повертає всі позики), і для `member` (повертає лише власні позики учасника). Варто уточнити JSDoc, щоб він відповідав поведінці `listLoans`.
- **[Правило 12] Зайве клонування всіх об'єктів до пагінації (Fowler Smell)**: Виклик `listLoans(db, user)` спочатку створює поверхневі копії (`rows.map((l) => ({ ...l }))`) для всіх 3 000+ записів, і лише потім `listLoansPage` бере зріз `.slice(start, start + pageSize)` на 20 елементів. Ефективніше спочатку відфільтрувати масив і взяти потрібний `slice`, а клонувати об'єкти вже лише для обраної сторінки.

## 4. Аналіз тестів та верифікації
- Наявний тест має критичний **Verification Gap**: він тестує лише те, що функція повернула передані їй параметри `page: 1` і `pageSize: 20` та загальну кількість `total: 7`, але не перевіряє головний результат роботи функції — масив `res.items`.
- Відсутні тести на багатосторінкову вибірку (перевірка, що сторінка 1 і сторінка 2 при малому `pageSize`, наприклад `pageSize: 3`, повертають правильні непересічні підмножини ID позик, а остання сторінка містить залишок).
- Відсутні негативні тести на некоректні параметри пагінації (`page < 1`, `pageSize <= 0`, перевищення максимального `pageSize`) та перевірка поведінки при `user = null`.
